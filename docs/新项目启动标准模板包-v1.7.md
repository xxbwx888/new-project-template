# 新项目启动标准模板包

> 版本：v1.7 ｜ 建立：2026-09-16 ｜ 更新：2026-11-15
> 适用：我们的所有项目，包括已有、新建、迁移及交接项目；两项 Skill 的永久默认启用规则见第三节。
> 本文件是使用说明和模板集合。**不要把整份文件改名为 `AGENTS.md`；只提取对应代码块。**

## 一、启动项目：先做这五步

配套 ZIP 已按下方结构拆好文件和目录。解压到新项目后，可直接从第 3 步填写；已有项目仍需先比较同名文件。

1. **准备目录**：在项目根目录建立下方目录结构；已有项目先检查同名文件，合并内容，不直接覆盖。
2. **放入模板**：提取第八节的六个文件模板，并把第十一节两份 Skill 原文、许可证及来源说明按指定路径保存；配套 ZIP 已全部拆好。`templates/接手模板.md` 是备用模板，初始化时不生成根目录 `接手.md`。
3. **填写规则**：填写 `AGENTS.md` 的项目定位、核心入口、专属红线、数据约定与交付标准；不适用的字段写“不适用”。
4. **确定第一步**：在 `STATE.md` 写清目标、范围、可观察的验收条件与第一条可执行待办；未验证的环境、命令和路径明确标记“未验证”。
5. **检查后开工**：完成第九节检查，记录一条“项目初始化”时间线，从第一条待办开始。

目录结构：

```text
项目根/
├── AGENTS.md                  # 稳定规则与工作入口
├── STATE.md                   # 当前状态、待办与恢复点
├── 避坑.md                    # 风险检查、失败经验与验证方法
├── 时间线.md                  # 最近 30 条实际变更
├── 接手.md                    # 仅在“写接手文档”时生成
├── .agents/
│   └── skills/                # 随项目携带的 Skill 原文，首次使用时读取
│       ├── SOURCES.md          # 来源、固定版本及 SHA-256
│       ├── find-skills/
│       │   ├── SKILL.md
│       │   └── LICENSE
│       └── grill-me/
│           ├── SKILL.md
│           └── LICENSE
├── templates/
│   └── 接手模板.md             # 生成接手文档时使用
└── timeline/
    ├── INDEX.md               # 历史及接手归档索引
    ├── archive/               # 移出的旧时间线条目
    └── 接手归档/              # 已消费或被替代的接手快照
```

## 二、每个文件只负责一件事

| 文件 | 负责什么 | 何时更新 | 何时读取 |
|---|---|---|---|
| `AGENTS.md` | 稳定规则、入口、红线、交付约定 | 规则或入口变化 | 开工时确认适用规则；已加载则不重复读取 |
| `STATE.md` | 当前目标、事实、待办、阻塞、恢复点 | 当前状态改变 | 开工、恢复或接手时 |
| `避坑.md` | 风险触发条件、失败原因、处理办法、验证证据 | 新坑、复发、修复验证或规则失效 | 先扫速查表，再读本任务命中的条目 |
| `时间线.md` | 最近 30 条实际变更及证据入口 | 有实际变更时聚合记录 | 按关键词查历史，不默认全文读取 |
| `timeline/INDEX.md` | 历史文件位置、时间范围、条目数 | 发生归档时 | 定位较早历史或交接记录 |
| `接手.md` | 本次交接的状态快照、未完步骤和关键上下文 | 用户说“写接手文档”时 | 用户说“接手”或“接手任务”时 |
| `templates/接手模板.md` | 接手文档的标准结构 | 交接格式变更 | 生成接手文档时 |
| `.agents/skills/grill-me/SKILL.md` | 永久默认启用的需求澄清原文 | 明确升级来源版本时 | 每个新会话、接手或恢复时确保已加载；每项需求均应用 |
| `.agents/skills/find-skills/SKILL.md` | 永久默认启用的技能发现原文 | 明确升级来源版本时 | 每个新会话、接手或恢复时确保已加载；每项新任务及范围变化前执行匹配检查 |
| `.agents/skills/SOURCES.md` 与各 `LICENSE` | 来源、版本、校验及授权声明 | 原文更新时同步 | 追溯来源或升级时 |

分工原则：规则放 `AGENTS.md`，事实放 `STATE.md`，经验放 `避坑.md`，过程放时间线。其他文件引用原处，避免维护多份相同正文。`接手.md` 允许保留带时间的精简快照，核验后的最新事实仍回写 `STATE.md`。

## 三、两项 Skill 永久默认启用与四条工作纪律

### 强制规则：所有项目永久默认启用两项 Skill

**我们所有项目的 `find-skills` 和 `grill-me` 必须永远默认启用。** 本规则覆盖已有项目、新建项目、迁移项目和交接项目，并持续适用于每个会话、每项任务及其后续执行过程。

1. **无需用户触发**：不得等待用户点名 Skill、输入调用命令或再次确认；不得因任务简单、换 Agent、换机器、重开会话、上下文压缩或恢复任务而自行停用、遗忘或降为可选。
2. **两份原文必须加载**：进入新会话、接手或恢复任务时，确保已读取 `.agents/skills/find-skills/SKILL.md` 和 `.agents/skills/grill-me/SKILL.md`；同一上下文已完整加载时不重复读，但持续执行。
3. **`grill-me` 负责每项需求的理解与澄清**：先核对目标、范围、约束、验收及决策依赖；有未决问题时按原文每次问一个问题，并给出建议答案，直到形成共同理解。能通过一次短检查查明的事实先自行查证；继续探索成本较高、且有具体依据表明用户能明显缩短路径时，按“探索止损与主动协作”规则求助。信息已充分明确时，完成核对即可继续执行，技能仍保持启用，不重复询问已解决事项。
4. **不设置临时关闭机制**：两项 Skill 都是常驻必选规则。原文的调用提示、`disable-model-invocation` 元数据仅按原样存档，不作为本模板自动停用或等待触发的依据。只有用户之后明确修订这条常驻规则，才调整项目政策；用户指定某次输出格式时照办，不视为关闭 Skill。仍遵守执行环境约束，不额外索要已经取得的授权。

此规则通过项目 `AGENTS.md` 要求 Agent 主动读取并执行。宿主未注册同名 Skill 时，直接读取随项目携带的原文；不以“未安装”或“未调用 Skill 工具”为由跳过。若文件缺失，先从本模板包第十一节的完整原文恢复，并如实标记缺口；恢复前不得声称已完成加载。原文保存位置统一为 `.agents/skills/`。

适用范围是所有项目；本模板文件本身不会自动改写其他项目或机器的配置。既有项目在迁移时须同步本规则及两份原文，并按第九节核验。

### 1. 默认执行 grill-me，先建立共同理解

- 每项新需求及范围调整都先执行 `grill-me` 的理解核对，不以用户是否点名或问题是否复杂作为启用条件。
- 需要澄清时每次问一个问题并附建议答案，沿决策依赖逐项问清；能由项目资料或工具通过短检查查明的事实先自行确认；成本高且用户能明确缩短路径时，可按探索止损规则提前求助。
- 已明确或已授权的事项不重复确认；信息充分时继续已授权工作，仍保持两项 Skill 生效。
- 缺少信息时继续推进不依赖该信息的部分；依赖用户答案或授权的动作保持待定。
- 确定的目标、范围、约束和验收条件写入 `STATE.md`，不让聊天记录成为唯一依据。

### 2. 默认执行 find-skills，先查现成技能

**每项新任务及关键范围变化前，必须执行 `find-skills` 的技能匹配检查；不等待用户说“帮我找 Skill”。** 本项目采用“先已有、后公开”的检查顺序，原文完整保留在 `.agents/skills/find-skills/SKILL.md`。

1. **先查已有技能**：结合任务目标、领域和技术栈，检查宿主已提供的技能清单、项目 `.agents/skills/` 及相关已安装技能；不能只因存在这两项常驻技能，就认定已有完成业务任务的专用技能。匹配时读取候选原文，确认可用后直接使用，不重复安装。
2. **缺口再查公开来源**：没有适用的已有技能时，按原文查看 `skills.sh`，必要时执行 `npx skills find <任务关键词>`；命令示例中的尖括号需替换。根据实际领域选择关键词，先查明候选内容再作推荐。
3. **核验后引入**：读取候选 `SKILL.md`，核对来源、任务适配、依赖与运行要求；安装量和星标仅作为参考。技能搜索不等于无条件安装，按用户已有授权及明确范围引入，不重复索要已获得的授权；范围不足时说明具体候选和拟安装位置。
4. **复用有效结论**：在 `STATE.md` 的“Skill 匹配记录”保留本任务结论。同一任务、范围和能力需求未变时沿用结论，不每轮重复联网；新增能力、环境或相关技能变化使旧结论不再适用时重新检查。复用结论仍属于执行检查，不代表停用 `find-skills`。
5. **如实处理无匹配与失败**：没有合适技能时记录“已检索，未找到匹配”并继续任务；网络或 CLI 不可用时记录“检索未完成”、原因与待补检查，继续不依赖它的工作，不把失败写成无匹配。CLI 不可用可用网页查询，不为寻找技能无限重试或中断所有工作。

两个技能的协作顺序：`grill-me` 核对任务理解 → `find-skills` 检查现成能力 → 按匹配结果执行。这里规定项目检查顺序，不改写第三方 Skill 原文。

### 3. 优先复用，按需搜索开源

- 新增能力、引入依赖或遇到陌生技术问题时，先查项目已有实现和官方资料，再按需搜索 GitHub 等来源。
- 文字修改、小修复、已有成熟方案的重复步骤，不要求每个子任务重新搜索。
- 评估现成方案的功能适配、许可证、维护状况、运行成本和兼容性；星标数量不代替判断。
- 只有需要本地评估或修改时才 clone/fork；采用的方案记录来源、版本和取舍，不自动运行未经检查的安装脚本。
- 记录影响后续决策的结论即可；无需逐条保存无关搜索结果。

### 4. 探索止损与主动协作

**Agent 必须自主判断：继续探索是否仍能获得有效证据，换一条路径或问用户一个问题是否能更快达到验收目标。出现无效试错时停止重复当前路径，不能靠增加工具调用维持“正在工作”的状态。**

#### 何时先停下来复盘

| 观察到的情况 | 应做什么 |
|---|---|
| 同一阻塞点连续两次有针对性的尝试，都没有新证据 | 暂停该路径，核对假设和替代入口；不继续机械换参数重试。 |
| 无有效进展的探索约 10 分钟，或下一步可能再花 10 分钟以上 | 比较继续探索、使用现成能力、向用户求助的预期成本。时间是提醒复盘的默认参考，不是到点就问人的硬限制。 |
| 为解决小问题开始准备新工具、复杂绕路或扩大改动范围 | 在实施前核对有没有现成入口、已有命令或更短路径；超出授权的改动仍需处理授权边界。 |
| 一项关键假设未经验证，后续探索反复围绕它失败 | 先设计能验证该假设的最小检查，不继续建立在猜测上的分支。 |

“新证据”应能缩小原因范围、排除方案或验证下一步；同一错误反复出现、重复全文读取、仅增加搜索结果不算新进展。正常等待下载、构建、训练或后台作业不计为盲目探索；先看实际状态和日志，不能仅因耗时较长就中止、重启或重复提交。

#### 复盘后如何自主决定

1. **先做一次短复盘**：默认用 1–2 分钟回到目标和验收，列明当前假设与已有证据；检查已知的现成工具、直接页面入口、官方说明、已有命令、Skill 匹配结论和相关避坑条目。不要重读全部历史或重新无限搜索 Skill。
2. **有明确下一步就自主验证**：能说清“这次验证哪个假设、预期获得什么证据、何时结束”，且属于已授权低风险操作时，选最有依据的短路径做一次有边界的验证。持续获得有效证据就继续；仍无新证据则不沿同一方案无限延长，不因改写计划就重置止损判断。
3. **用户的一句话能改变路线时主动问**：缺少用户独有信息、必要权限或业务取舍时提问；即使理论上还能自行查，若有具体依据表明用户熟悉现成入口或既有操作路径，预计 1–2 分钟的回答可替代至少约 10 分钟的低收益探索，也可提前求助。估计应标明为估计，不凭“用户可能更快”就中断任务；能用一次短检查查明的事实先自行检查。
4. **一次只问一个关键问题**：用 `grill-me` 的方式说明已确认的事实、已试方法及结果、需要什么答案，以及答案如何改变下一步；有业务选项时给推荐选项。不要只说“卡住了，怎么办”，不要向用户倾倒日志，也不让用户重复提供已有信息。暂停受该答案影响的部分，继续其他已授权且独立的工作。
5. **等待与恢复有记录**：用户暂未回复时，把卡点、失败尝试、当前判断、待答问题和可继续事项写入 `STATE.md`；不重复催问，不把等待当作同意。没有新证据、环境变化、有效替代路径或用户答案时，不重启已停止的无效分支；收到答案后更新状态并从最短可行步骤继续。

提问格式（按实际证据填写）：

> 我已确认【事实】，尝试【方法】后仍缺少【信息】。继续自行排查预计还需【时间】。请确认【一个会改变路线的问题】；得到答案后我会【下一步】，期间继续【独立工作，如有】。

已验证的失败模式与解决办法归入 `避坑.md`；尚未验证的判断只留在 `STATE.md`，不写成成功经验。用户协助用于减少弯路，不改变自动化目标，不绕过验证码、权限或隐私确认，不擅自重设计现有认证流程。

## 四、开工与日常维护

### 开工读取顺序

1. 确认适用的 `AGENTS.md`，确保 `find-skills` 与 `grill-me` 两份原文均已加载并持续生效，再读 `STATE.md` 的目标、当前进度和下一步；已完整加载只免除重复读取，不免除执行。
2. 扫 `避坑.md` 速查表，读取与当前任务有关的条目；文件不存在时标记缺口，不假装已检查。
3. 执行 `find-skills` 匹配检查或复用同任务有效结论，选一条有明确验证目标的短路径；验证关键路径、命令、运行状态和产物，需要历史时才定向查询。后续探索按止损规则持续判断，不等到穷尽所有方案才考虑求助。

只读与讨论不要求机械改写所有文档。任务结束或中断前，按实际变化维护：

| 发生的变化 | 写入位置 |
|---|---|
| 稳定约束、入口或验收方法改变 | `AGENTS.md` |
| 进度、待办、阻塞、Skill 匹配结论、探索复盘/待答问题、产物位置或恢复点改变 | `STATE.md` |
| 新发现失败模式、修复已验证或旧经验失效 | `避坑.md` |
| 代码、配置、数据、产物或上述文档实际改变 | `时间线.md`，同一任务写一条聚合记录即可 |
| 时间线或接手文件归档 | `timeline/INDEX.md` |

时间线记录“变更 + 结果 + 证据路径”；失败、回滚和验证不足同样如实记录。纯阅读不记流水账；讨论形成并落盘的决策可以记一条。

### `避坑.md` 的维护边界

- **预防检查不是事故记录**：新项目可预置风险检查，但不得编造“已经踩过”或“验证通过”。
- **一坑一编号**：使用 `PIT-001` 起的稳定编号。复发时补充同一条，避免同一问题多处重复。
- **区分判断与事实**：原因不明写“待验证”；只有修复和验收证据齐全才标“已验证”。
- **规则短，证据另存**：硬性约束提炼到 `AGENTS.md`，在避坑条目保留原因、处理步骤和证据入口；长日志放已有日志目录。
- **失效保留原因**：环境或版本变化后标“已失效”，写清替代条目。该文件明显变长时，保留有效速查，将失效正文迁到 `timeline/archive/` 并登记索引。

## 五、接手机制

| 用户触发词 | Agent 应做的事 |
|---|---|
| **写接手文档** | 先同步当前状态、未验证事项和相关避坑条目，再按 `templates/接手模板.md` 生成项目根 `接手.md`。若旧文件仍存在，先以唯一文件名归档并登记索引，再生成新版。 |
| **接手 / 接手任务** | 在遵守适用规则的前提下，先读 `接手.md`，再核对 `STATE.md` 和相关避坑条目；检查关键现场证据，将差异回写当前状态后，按已有授权继续可执行待办。 |

接手后的处理：

1. 核验完成且必要信息已进入长期文档后，把 `接手.md` 移到 `timeline/接手归档/接手-YYYYMMDD-HHMMSS-001.md`，并登记索引；无需等全部待办做完。

## 六、唯一归档规则

本版只采用**最近 30 条 + 超出条目归档 + 索引**，不再并行使用按月迁移和整页快照两套规则。

1. `时间线.md` 按时间从旧到新追加，每条实际变更占一行；最新记录在底部，说明文字不计入条数。
2. 超过 30 条时，仅把超出的最旧条目原样写入 `timeline/archive/时间线-YYYYMMDD-HHMMSS-001.md`；遇同名递增序号。
3. 核对归档条目数、首尾时间及原文一致性，确认文件已保存；失败时保留原时间线并停止归档。
4. 校验成功后才从 `时间线.md` 移除已归档条目，在 `timeline/INDEX.md` 登记归档路径、范围、条数和摘要。
5. 归档中断后先比对索引、归档文件与原条目，补齐缺失步骤，避免重复归档或丢记录。归档本身不再生成一条时间线，避免循环。

# Find Skills

This skill helps you discover and install skills from the open agent skills ecosystem.

## When to Use This Skill

Use this skill when the user:

- Asks "how do I do X" where X might be a common task with an existing skill
- Says "find a skill for X" or "is there a skill for X"
- Asks "can you do X" where X is a specialized capability
- Expresses interest in extending agent capabilities
- Wants to search for tools, templates, or workflows
- Mentions they wish they had help with a specific domain (design, testing, deployment, etc.)

## What is the Skills CLI?

The Skills CLI (`npx skills`) is the package manager for the open agent skills ecosystem. Skills are modular packages that extend agent capabilities with specialized knowledge, workflows, and tools.

**Key commands:**

- `npx skills find [query] [--owner <owner>]` - Search for skills interactively or by keyword, optionally scoped to a GitHub owner
- `npx skills add <package>` - Install a skill from GitHub or other sources
- `npx skills update` - Update all installed skills

**Browse skills at:** https://skills.sh/

## How to Help Users Find Skills

### Step 1: Understand What They Need

When a user asks for help with something, identify:

1. The domain (e.g., React, testing, design, deployment)
2. The specific task (e.g., writing tests, creating animations, reviewing PRs)
3. Whether this is a common enough task that a skill likely exists

### Step 2: Check the Leaderboard First

Before running a CLI search, check the [skills.sh leaderboard](https://skills.sh/) to see if a well-known skill already exists for the domain. The leaderboard ranks skills by total installs, surfacing the most popular and battle-tested options.

For example, top skills for web development include:
- `vercel-labs/agent-skills` — React, Next.js, web design (100K+ installs each)
- `anthropics/skills` — Frontend design, document processing (100K+ installs)

### Step 3: Search for Skills

If the leaderboard doesn't cover the user's need, run the find command:

```bash
npx skills find [query] [--owner <owner>]
```

For example:

- User asks "how do I make my React app faster?" → `npx skills find react performance`
- User asks "can you help me with PR reviews?" → `npx skills find pr review`
- User asks "I need to create a changelog" → `npx skills find changelog`

### Step 4: Verify Quality Before Recommending

**Do not recommend a skill based solely on search results.** Always verify:

1. **Install count** — Prefer skills with 1K+ installs. Be cautious with anything under 100.
2. **Source reputation** — Official sources (`vercel-labs`, `anthropics`, `microsoft`) are more trustworthy than unknown authors.
3. **GitHub stars** — Check the source repository. A skill from a repo with <100 stars should be treated with skepticism.

### Step 5: Present Options to the User

When you find relevant skills, present them to the user with:

1. The skill name and what it does
2. The install count and source
3. The install command they can run
4. A link to learn more at skills.sh

Example response:

```
I found a skill that might help! The "react-best-practices" skill provides
React and Next.js performance optimization guidelines from Vercel Engineering.
(185K installs)

To install it:
npx skills add vercel-labs/agent-skills@react-best-practices

Learn more: https://skills.sh/vercel-labs/agent-skills/react-best-practices
```

### Step 6: Offer to Install

If the user wants to proceed, you can install the skill for them:

```bash
npx skills add <owner/repo@skill> -g -y
```

The `-g` flag installs globally (user-level) and `-y` skips confirmation prompts.

## Common Skill Categories

When searching, consider these common categories:

| Category        | Example Queries                          |
| --------------- | ---------------------------------------- |
| Web Development | react, nextjs, typescript, css, tailwind |
| Testing         | testing, jest, playwright, e2e           |
| DevOps          | deploy, docker, kubernetes, ci-cd        |
| Documentation   | docs, readme, changelog, api-docs        |
| Code Quality    | review, lint, refactor, best-practices   |
| Design          | ui, ux, design-system, accessibility     |
| Productivity    | workflow, automation, git                |

## Tips for Effective Searches

1. **Use specific keywords**: "react testing" is better than just "testing"
2. **Try alternative terms**: If "deploy" doesn't work, try "deployment" or "ci-cd"
3. **Check popular sources**: Many skills come from `vercel-labs/agent-skills` or `ComposioHQ/awesome-claude-skills`

## When No Skills Are Found

If no relevant skills exist:

1. Acknowledge that no existing skill was found
2. Offer to help with the task directly using your general capabilities
3. Suggest the user could create their own skill with `npx skills init`

Example:

```
I searched for skills related to "xyz" but didn't find any matches.
I can still help you with this task directly! Would you like me to proceed?

If this is something you do often, you could create your own skill:
npx skills init my-xyz-skill
```
