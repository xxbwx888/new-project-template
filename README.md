# new-project-template

给 AI Agent 用的项目启动模板：一套让项目在**换会话、换机器、换 Agent 之后仍然知道自己该守什么规则**的文件骨架。

不依赖任何框架、插件或脚本，解压即用；文件全是 Markdown，任何编辑器、任何 Agent 都能读。

## 它解决什么问题

Agent 会话是短命的。同一件事过一周再问，模型不记得上次为什么那样做、踩过哪些坑、哪些规则是硬约束。把规则、事实、经验、过程分别落在固定的四个文件里，每次开工按顺序读，就能把上下文重新装配起来：

| 文件 | 只负责一件事 | 何时更新 |
|---|---|---|
| `AGENTS.md` | 稳定规则、入口、红线、交付约定 | 规则或入口变化 |
| `STATE.md` | 当前目标、事实、待办、阻塞、恢复点 | 当前状态改变 |
| `避坑.md` | 风险触发条件、失败原因、处理办法、验证证据 | 新坑、复发、修复验证 |
| `时间线.md` | 最近 30 条实际变更及证据入口 | 有实际变更时聚合记录一条 |

分工原则是**规则放 `AGENTS.md`，事实放 `STATE.md`，经验放 `避坑.md`，过程放时间线**，其他文件引用原处，避免同一段正文维护多份。

## 目录结构

```text
项目根/
├── AGENTS.md                  # 稳定规则与工作入口
├── STATE.md                   # 当前状态、待办与恢复点
├── 避坑.md                    # 风险检查、失败经验与验证方法
├── 时间线.md                  # 最近 30 条实际变更
├── .agents/skills/            # 随项目携带的 Skill 原文
│   ├── SOURCES.md             # 来源、固定版本及 SHA-256
│   ├── find-skills/
│   └── grill-me/
├── docs/
│   └── 新项目启动标准模板包-v1.7.md   # 完整使用说明与全部文件模板
├── templates/
│   └── 接手模板.md             # 生成接手文档时使用
└── timeline/
    ├── INDEX.md               # 历史及接手归档索引
    ├── archive/               # 移出的旧时间线条目
    └── 接手归档/              # 已消费或被替代的接手快照
```

`接手.md` 不在初始化时生成，只在需要交接时按模板产出。

## 用法

1. 把本仓库的文件复制到新项目根目录（或直接用本仓库当起点）。
2. 读 `docs/新项目启动标准模板包-v1.7.md`。**不要把这份说明改名成 `AGENTS.md`**——它包含多个模板，`AGENTS.md` 只是其中一节；直接从仓库根的 `AGENTS.md` 开始填。
3. 填 `AGENTS.md` 的定位、核心入口、专属红线、数据与交付约定；不适用的字段写“不适用”。
4. 在 `STATE.md` 写清目标、可观察的验收条件、第一条可执行待办；未验证的环境和路径明确标注“未验证”。
5. 走完模板包第九节的初始化检查清单，写一条“项目初始化”时间线，从第一条待办开始。

## 两项常驻 Skill

模板默认要求 `grill-me`（需求澄清：每次问一个问题并给出建议答案）与 `find-skills`（技能发现：先查已有、再查公开来源）永久启用，原文随项目携带在 `.agents/skills/`，宿主未注册同名 Skill 时直接读原文执行。

两项原文分别来自 [mattpocock/skills](https://github.com/mattpocock/skills) 与 [vercel-labs/skills](https://github.com/vercel-labs/skills)，均为 MIT 许可，固定提交与 SHA-256 见 `.agents/skills/SOURCES.md`；原文一字未改，启用政策写在 `AGENTS.md` 而不是改写 Skill 元数据。

如果不需要这条常驻规则，删掉 `AGENTS.md` 里那一节和 `.agents/skills/` 即可，其余部分独立可用。

## 几个设计取舍

- **归档规则只有一套**：时间线超过 30 条，只把最旧的条目原样移入 `timeline/archive/时间线-YYYYMMDD-HHMMSS-001.md`（同名递增，不覆盖），核对数量与首尾后从原文件删除，并登记 `timeline/INDEX.md`。不用按月迁移，不做整页快照。
- **事实有优先级**：`AGENTS.md` 硬规则 > 实际产物与测试 > `STATE.md` 当前摘要 > 任务 checkpoint > 时间线历史。发现冲突时改 `STATE.md`，不把历史日志当现行配置。
- **避坑条目要证据**：只有处理办法和验证结果都有证据才能标“已验证”；原因没证实就写“假设，待验证”；失效的标“已失效”并写清替代办法，不静默删除。
- **探索有止损**：同一阻塞两次针对性尝试无新证据、或约 10 分钟无进展就复盘换路；用户 1–2 分钟能替代 10 分钟低收益探索时，只问一个关键问题。

## 说明

本仓库是内部模板的公开版。内部版本另有一节“知识库接入”（跨项目经验检索器），因其写有内网主机名、绝对路径与内部目录结构，公开版已整节移除；`AGENTS.md` 模板内的对应标记块、检查清单项与版本记录同步调整，其余内容原样保留。版本记录见 `docs/新项目启动标准模板包-v1.7.md` 第十节。
